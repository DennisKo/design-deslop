# Color and gradients

Inspect and improve the current palette and contrast within the manager’s assignment. Implement and verify justified changes unless the user requested review only.

## Identify

- Purple used as an unexplained default across backgrounds, buttons, headings, illustrations, and decoration.
- Purple gradients standing in for a deliberate palette or visual hierarchy.
- Neon gradient fills, glowing gradients, or rainbow accents that compete with content and actions.
- Neon or multicolor gradient borders added to ordinary controls, cards, or containers to make them look premium or AI-powered.

## Improve

Remove these patterns by default when they are incidental additions. Establish a palette from the product's purpose, audience, existing identity, imagery, and content. Choose deliberate surface, text, action, and semantic colors. Give the primary action clear emphasis; reduce competing accents elsewhere. Prefer a solid fill, a conventional border, or no border when that communicates the element's role adequately.

Do not replace every purple interface with mandatory beige, monochrome, or another fashionable preset. A distinctive palette can remain colorful. Judge color by its function and relationships rather than treating a particular hue as inherently bad.

Preserve explicitly required brand colors and gradients. Keep gradients that communicate continuous data values or serve a specific requested visual concept. Preserve meaningful status distinctions and visible keyboard focus; do not trade accessibility or comprehension for restraint. Check readable text and control contrast on actual backgrounds, including interactive states.

Coordinate with the decoration module when removing a gradient border changes container hierarchy. Coordinate with typography when accent color currently supplies necessary heading emphasis.

## Return

Report the color changes made, contrast checks, unresolved dependencies, and verification limits. Avoid unsupported claims that a palette has passed accessibility checks.

Return the short specialist handoff defined in SKILL.md: completed changes, files, checks, and any limits or dependencies. In review-only mode, report recommendations instead. Do not create report files or start another round of subagents.
